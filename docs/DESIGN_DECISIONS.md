# Design decisions

- Demand uses a project-week `DemandPlan` header identifier and separate role/skill `DemandLine` records. Thus each project-week can contain multiple role/skill requirements while retaining the specified `DEM-<project>-<week>` identifier.
- Source tables are generated before derived availability, utilization, supply, gap, and action records. Anomaly injection modifies source fields before derived tables are recalculated.
- Seed streams use a deterministic NumPy `SeedSequence` spawn key per entity family. Independent entity generation is isolated from changes to other families.
- The database enforces primary keys, foreign keys, and row-level checks. Business-key uniqueness for approved demand is checked in Python so anomaly fixtures can be loaded.
- The configured 2% anomaly rate is applied independently to each eligible target population, with at least one example for each required anomaly family. Ground truth keys are source record IDs so evaluation can match detections without detector access to labels.
- Pipeline confidence is configured in `config/default.yaml`: Planned 0.45, Active 0.8, Completed 0.0, and Cancelled 0.0. Historical backtests recompute project lifecycle as of each origin date and exclude plan lines created after that origin.
- Baseline allocations target at least 1.5 allocations per employee, with a configured 20% employee share receiving concurrent Shared-Pool allocations. The overlap pair is capped at 100%; the remaining additional assignments are sequential and separated by ISO-week boundaries so weekly utilization remains consistent. Dedicated-Team members have no baseline overlaps. The anomaly injector samples isolated eligible allocations so legal baseline overlaps are not mislabeled as injected over-allocation.
- Leave targets 80% employee coverage, two non-overlapping Monday–Friday absences and one short absence per eligible employee. Configured monthly weights span the full calendar, with elevated July, August, and December probability. Availability continues to subtract approved leave using the existing daily FTE calculation; the full-week records intentionally create zero-availability weeks.
- Each project carries a generated `demand_profile` (`ramp_up`, `steady`, or `ramp_down`). Configured ramp factors scale line-level FTE over the project schedule, while the independent configured zero-demand probability still omits whole project-weeks. Append-only Superseded revisions remain separate from the curve generation.
- The full-scale baseline measurement found 450 over-utilized employee-weeks, all 450 attributable to injected allocation anomaly type (a), so the legal high-utilization band is separately represented as a non-anomalous planning risk. `risk_level` is `High` when available-hours utilization is within the configured inclusive 0.9–1.0 band; it emits a traceable Reallocate review action even when the allocation is legal. Above 1.0, `risk_level` is `Overutilized` and Reallocate is emitted to correct the excess. Above the higher configured contract threshold (1.2), Contract is also emitted: this is a distinct HR sourcing/capacity response, while Reallocate changes assignments. Estimated excess-hour cost above the configured budget cap is Escalated. Both action types link their source utilization row and applicable allocation IDs.
- The original pipeline-adjusted method's `bias == -WAPE` is not a metric bug: its evaluated predictions were never above actuals. Under this repository's bias convention, if every cell has `prediction <= actual`, then `sum(abs(actual - prediction)) == sum(actual - prediction)`, so WAPE is exactly the negation of bias. The confidence-weighted pipeline omits demand not yet created at each origin and applies confidence values below one, explaining its systematic undershoot.
- `pipeline_realization_adjusted` multiplies each origin's pipeline predictions by a ratio learned from disjoint, completed four-week historical blocks. Both historical forecasts and realized demand are cutoff at the training origin; the ratio is clipped to configured bounds, and the same no-look-ahead rule is tested for future lines.
- `forecast_project.csv` splits the role-level moving-average prediction by each project's share of the role's demand in the four visible historical weeks. Pipeline predictions use only Approved target-week lines created by the origin, weighted by lifecycle confidence; realization adjustment applies the same origin-specific scalar. The project rows are rounded with a deterministic residual assignment so their totals exactly reconcile to `forecast.csv`; validators test this at generation and on exported files.
- Near-miss controls are generated as ordinary unlabeled source rows: an exact-100% Shared-Pool allocation group, an EmployeeSkill expiring exactly on the as-of date, same-role/skill demand in adjacent weeks, and adjacent-week-boundary Dedicated-Team allocations. The anomaly injector excludes these eligible negative records from target selection; the detector still receives no labels or fixture IDs.
